# PBF 优化进度总结

更新日期：2026-10-23。范围：本次对话从首次 NSYS/NCU 分析，到邻域缓存、边界结果复用、代码整理和最新性能复查。当前待办见 [issue.md](issue.md)。

同配置、同模拟时间段的 NSYS 纯求解耗时从 **21.067 ms/帧降至 7.016 ms/帧，约加速 3.00 倍，耗时下降 66.7%**。这是多项修改组合后的整体收益，没有逐项消融数据，不能将总收益全部归于其中一项。

## 1. 对比条件与整体收益

| 项目 | 对齐条件 |
|---|---|
| 设备与运行时 | RTX 5070，Warp 1.15.0 |
| 场景 | stairs_scene.nvdb，体素间距 0.0075 m |
| 粒子数 / 支撑半径 | 205,379 / 0.05 m |
| 帧时间 | 1/90 秒 |
| 子步 / 每子步压力迭代 | 3 / 3 |
| lambda、delta、update_prePos | 各 9 次/帧 |
| cache_neighbors、curl、visvor | 各 3 次/帧；旧版没有独立缓存构建核 |
| NSYS 测量 | 从初始化预热 1,800 帧，采集 120 帧，模拟时间约 20–21.333 秒 |

新版先保存预热状态；恢复采集前预加载模块，再还原物理状态，正式计时从相同的 20 秒状态开始。旧新版初始化配置与时间段一致，但浮点运算和轨迹不保证逐粒子完全相同。

上述新版计时包含当时仍存在的 Epilogue 重复 `grid.build`。之后该调用已删除，当前 NCU 也来自删除后的版本，但尚未重新测量删除后的正常整帧耗时。不能将预计节省的时间从 7.016 ms 中直接扣除并当成实测值。

## 2. 已完成的优化与配套工作

### 2.1 基线分析与优化顺序

- 初始 NSYS 确认压力两核占 CUDA kernel 时间约 74.4%，lambda、delta、curl、visvor 四核合计约 95.3%。
- 初始 NCU 显示间接访存、线程分歧和压力核寄存器限制；另一固定状态中平均约 249 个候选、43 个有效邻居，约 83% 候选被距离检查剔除。
- 分析了边界/体积图、网格构建、主机同步、渲染与启动预计算成本，区分稳定帧耗时和初始化耗时。
- 将邻域缓存列为高优先级、块大小对照列为中优先级。当前块大小仍未完成 A/B 实测。

### 2.2 有效邻域缓存与粒子物理重排

- 每子步在预测位置上构建网格，按网格排序同步重排 `pos` 与 `pre_Pos`，保持粒子对应关系，供速度重建使用。
- 使用 `sorted_index(query)` 将查询游标对应到排序后的数组槽位，缓存编号对应重排后的工作数组；当前不需要额外保留两份粒子 ID 映射。
- 构建 `n_Cache`，包含 `NeighborCount` 与 `CacheBuffer`；索引布局为 `[邻居槽位, 粒子]`，同一槽位下相邻线程的读取连续。
- 每子步只构建一次有效名单，供 lambda、delta、curl、visvor 复用，将反复的候选查询与筛选集中到缓存构建阶段。
- 不再依靠 `pre_New` 快照反复查询。预测位置保留在 `pre_Pos`，后续读取缓存编号并使用当前粒子位置；缓存只保存编号，距离、方向与核值按使用时的位置计算。
- 名单包含自身：lambda 保留自密度及原有自身梯度处理，其余邻域操作按现有逻辑跳过自身。

当前容量为 192，最新场景平均约 42.56 个邻居、P95 为 49、最大 55。用户已测试极限邻域数量，本版维持固定容量，容量不足时增大，不新增溢出检测、自动扩容或回退策略。

固定名单不会自动补入后续移入半径的新邻居，这是已接受的计算量与精度取舍，并非已解决的正确性问题。名单刷新对照继续保留为最低优先级待办。

### 2.3 SDF 与体积图边界梯度复用

- 新增每粒子一个 `vec3` 的 `volume_Grad`，205,379 粒子约增加 2.46 MB 工作内存。
- lambda 在原有 SDF、体积图查询中计算并写出边界梯度，无有效边界时明确写零。
- 紧接着的 delta 直接读取梯度，移除同一位置上的重复 SDF、法线与体积图查询。
- 每次压力迭代重新写入；lambda 与 delta 之间位置不更新，下一轮按更新位置重新查询。
- 缓存在使用前被逐粒子覆盖，无需随粒子重排；重置时清零。
- `update_prePos` 对修正后位置的 SDF 查询保留，不能复用修正前的查询结果。

当前 NCU 中，delta 相对初始版本的寄存器从 **67 降至 35**，实际占用率从 **45.5% 升至 89.3%**，local 读写归零。这与边界查询已移出相符；其独立帧收益仍需单项消融区分。

### 2.4 平滑核接口与重复几何代码整理

- 当前 `Poly6(pos, neighbor_pos)` 与 `GradPow3(pos, neighbor_pos)` 接收两个位置，在函数内完成对应的位移、距离与核计算。
- 平滑半径使用编译期常量 `Smoothing_Radius`，不在调用处逐次传入。
- 整合并移除旧距离参数版 Poly6 和 DPow3；密度核使用距离平方，梯度核在需要时再开方、归一化。
- 保留支撑半径检查；梯度在零距离时返回零，避免不同粒子重合时除零；lambda 的自密度不因零距离判断而被删除。
- `calc_visvor` 保留原有范围检查，当前粒子的旋度幅值在循环前读入复用。

这一部分主要改善可读性和重复写法。编译器是否消除了跨平滑核调用的重复几何计算、独立获得多少收益，尚无单项实测；不将源码简化直接视为 GPU 指令减少。

### 2.5 重置、命名与现有测试适配

- 主类统一为 `PBF`，邻域数组统一为当前 `n_Cache.NeighborCount`、`CacheBuffer`，边界梯度缓存统一为 `volume_Grad`；创建入口与测试完成对应适配。
- `simulation.py` 连接前端创建、重力翻转与重置。重置在当前工作缓冲上恢复初始点阵，清零速度和工作数组，使邻域计数失效，并恢复重力和时间；复用原网格、SDF、体积图、渲染器资源。
- 补充/适配缓冲交换后的重置、重复重置、设备作用域、重置轨迹、邻域参数和边界梯度缓存相关测试。
- 平滑核测试覆盖自密度、零梯度、方向和支撑范围；边界测试包含有效与无效结果更新，检查无效边界不会遗留旧梯度。
- 本轮此前记录的 PBF 测试集 41 项已通过；最新两轮采集的位置、速度均为有限值。长期密度误差、边界穿透和名单刷新收益不因此视为已量化完成。

### 2.6 删除重复网格构建

Epilogue 的 `grid.build(self.pre_Pos, ...)` 已删除：后续速度邻域操作使用缓存，下一子步会重新构建网格。最新 NCU 对应源码已包含该修改。

此前按排序、索引和清零时间估计，它对应约 **0.174 ms/帧、约 2.5%** 的 GPU 时间预算。这是删除前的预算估算，尚无删除后的独立整帧 A/B 结果。

## 3. 尝试后撤回的结构方案

邻域循环曾尝试公共遍历函数、传入 kernel 对应计算函数，以及逐 kernel 的操作状态结构；之后也尝试过不使用操作状态结构的回调形式。根据可读性取舍，这些结构变更已撤回。

独立的 `neighbor_geometry` 也已撤回，最终采用两个位置参数的平滑核函数。当前不保留上述公共回调遍历和操作状态结构；`NeighborCache` 仍作为邻域数组载体。边界梯度缓存保留。

这些尝试作为设计过程记录，不计为当前保留的优化，也没有独立性能收益结论。

## 4. 分 kernel 的阶段性提升

以下为配置对齐的两次 NSYS 结果。缓存构建成本已计入新版总耗时。

| Kernel | 优化前 ms/帧 | 优化后 ms/帧 | 耗时下降 |
|---|---:|---:|---:|
| calc_lambda | 6.960 | 2.136 | 69.3% |
| calc_deltaPos | 7.670 | 1.055 | 86.2% |
| calc_curl | 1.965 | 0.458 | 76.7% |
| calc_visvor | 2.145 | 0.675 | 68.6% |
| update_prePos | 0.593 | 0.593 | 基本不变 |
| cache_neighbors | 无独立 kernel | 0.964 | 新增成本 |

变化同时包含缓存、重排、边界复用、函数实现及编译资源变化，不能据此拆分各项贡献。curl、visvor 的绝对耗时也明显下降；update_prePos 占比上升主要是其余 kernel 变快。

## 5. 当前瓶颈与简要后续方向

最新 NCU 每个目标核采集首次调用，使用 kernel replay 与缓存清理。下表的访存等待是 Long Scoreboard 在 warp 指令间周期中的比例，不是整帧时间或可节省比例。

| Kernel | 寄存器/线程 | 理论 / 实际占用率 | 访存等待占比 | 主要观察 |
|---|---:|---:|---:|---|
| lambda | 77 | 50.0% / 43.1% | 73.5% | 寄存器限制，每调度器可发射 warp 仅 0.42 |
| delta | 35 | 100% / 89.3% | 64.8% | 占用率已高，DRAM 吞吐约 63.3% |
| visvor | 47 | 83.3% / 76.7% | 80.5% | L2 命中约 90.9%，L2 吞吐约 82.2% |
| cache_neighbors | 40 | 100% / 82.8% | 24.4% | 调度效率相对较好，暂不优先重写 |
| update_prePos | 64 | 66.7% / 57.9% | 88.2% | 修正后位置的 SDF 查询延迟 |

1. **高：降低 lambda 的资源负担。** 独立比较边界查询与邻域计算分离，复用已有梯度并输出必要的边界密度项；计入新增 kernel 与缓存读写。当前 256 线程模型中，寄存器降至 64 或以下才支持 4 个驻留块；不直接强制寄存器上限。
2. **高：改善编号到属性的依赖访存。** 对 lambda、delta、visvor 分别尝试少量编号/属性提前读取，穿插本轮计算；保留累加顺序，检查新增寄存器是否抵消收益。现有缓存布局已支持同槽位跨线程连续读取。
3. **中：研究 SDF 插值路径。** 分析 lambda、update_prePos 的插值临时数组与 local 读写，评估展开或简化。local 流量不能直接视为寄存器溢出，不能复用不同位置的旧边界结果。
4. **中：小范围扫描块大小。** 比较 128/256；当前模型中 lambda 二者理论占用率同为 50%，不预设调小必然更快。
5. **低：缓存构建与主机提交。** 热点实验之后，再评估候选遍历、CUDA Graph 和同步；前次 NSYS 每帧 GPU 工作间隙约 0.61 ms，不能当作全部可回收时间。
6. **最低，暂缓：名单刷新与多实例。** 按既定取舍保留跨迭代的固定有效名单；同进程多实例的全局编译常量绑定问题仍未修复。

下一次性能复测应先覆盖已删除重复网格构建的当前版本，再对单个实验做 A/B。继续固定 3×3、同一保存状态、相同预热与采样窗口，比较无 profiler 均值/P95、NSYS 完整阶段和整帧耗时；NCU 用于解释硬件行为。

## 7. 新阶段：分离体积图处理与两层邻域预读（2026-10-23）

第 1–6 节保留上一阶段的实现、采样数据与当时的待办，不用本节结果覆盖或倒改历史记录。本节单独记录随后完成的两项优化，并以三个版本、三个粒子规模重新统一测量，避免把不同批次的百分比拼接。

### 7.1 本阶段实现与对照版本

| 版本 | 体积图处理 | 邻域读取 | 对照含义 |
|---|---|---|---|
| A：本阶段优化前 | lambda 内查询 SDF、法线与体积图 | 原邻域循环 | 已有邻域缓存、lambda→delta 梯度复用和删除重复网格构建 |
| B：仅分离体积图 | 独立 volume_query，输出 volume_Rho、volume_Grad | 原邻域循环 | A→B 衡量体积图分离的净收益 |
| C：分离＋两层预读 | 与 B 相同 | lambda、delta、curl、visvor 位置提前一位、编号提前两位 | B→C 衡量分离基础上的预读收益；A→C 为两项合计 |

- 分离体积图不减少原有查询次数，目标是减轻邻域 lambda 的资源负担；每次压力迭代仍重新查询。新增每粒子一个 float32 的 volume_Rho，三个规模分别约 0.82、1.62、4.00 MB，复用已有 volume_Grad。
- 预读只调整编号与位置的读取时机，累加顺序、公式、自身与半径判断保留；推进放在 continue 之前，空邻域在外层处理，尾部下标用 wp.min 钳制。没有回调、操作状态 struct 或逐邻居几何缓存。
- 本次整理只运行冻结的 A/B/C 快照与补充采集，不再次修改求解器。

### 7.2 统一测量口径

- RTX 5070、Warp 1.15.0、同一 stairs_scene.nvdb、同一容器与初始流体块；frame_dt=1/90、3 子步×3 次压力迭代、256 线程、关闭渲染。
- 20万、40万、100万实际分别为 59³、74³、100³，粒子半径分别为 0.0125、0.01、1.5/202 m。间距 d=2r、支撑半径 h=4r，三个规模均保持 h/d=2；不声称不同分辨率之间是相同粒子轨迹。
- 同一规模的 A/B/C 从完全相同的仿真 20 秒保存状态恢复，状态文件 SHA256 已核对一致。20万与百万使用已有保存状态；40万使用 A 预热 1,800 帧后保存。每版独立进程，编译预热后恢复状态。
- 无 profiler：5 批×120 帧，每批预热 5 帧后再次恢复状态，批次计时前后同步 GPU；下表取五批平均帧耗时的中位数。NSYS：每版每规模采集 120 帧；GPU 均值/P95来自时间线，不使用异步 CPU 返回耗时。
- A 每帧 72 个 CUDA kernel，B/C 每帧 81 个；新增 9 次体积图查询核启动及结果读写均计入收益。没有运行新的 NCU。

本节为这次统一补测结果，之前单项实验中的数值保留在原报告。没有锁定 GPU 时钟，运行环境与轨迹分布存在波动；无 profiler 与 NSYS 的降幅不必相同，不把单次采样比例解释为所有场景的固定收益。

### 7.4 NCU 解释与正确性边界

已有小规模 NCU 对照显示，分离后 lambda 为 42 寄存器，加入预读后为 48，理论占用率仍为 83.3%；eligible warps 从约 0.84 增至 2.20。delta 的寄存器 35→42，实际占用率约 90.5%→61.2%，动态指令增加约 11.6%、global-load 请求增加约 23.5%。四核访存等待均改善，local 读写均为零；请求数不等于显存字节数。

此前 20万/百万的预读 NSYS 对照中 delta 单核分别略慢约 3.7%/2.6%，不因整体收益为正而宣称每个核都更快。NCU 单次 delta 时间下降时 SM 时钟也更高，不能据此覆盖正常连续迭代的测量；delta 的独立策略比较仍保留待办。

本次统一补测的 delta 单核 B→C 则为：20万（205,379） 0.839→0.877 ms/帧；40万（405,224） 2.274→2.150 ms/帧；100万（1,000,000） 5.451→5.303 ms/帧。不同规模/批次的结果并不全同，因此继续保留单独策略对照，不用某一轮数据宣称恒定收益或恒定退化。

现有 PBF 测试此前 41 项通过，预读的四核同输入对照通过 rtol=2e-5、atol=1e-7。多帧轨迹并非严格等价：此前 C 对 B 的 10 帧对照中，20万/百万最大位置差约 1.65/4.51 mm，最大速度差约 0.65/1.21 m/s。本次三规模补测确认位置、速度有限，但未新增40万的长期精度验证，不能将性能采集完成等同于长期数值行为完全验证。
