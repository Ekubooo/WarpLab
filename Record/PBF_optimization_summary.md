# PBF 原版与流固耦合优化记录

整理日期：2026-11-06。本文浓缩已完成事项及已有实测，不替代逐轮报告。原版历史来自 [optimization.md](../demos/fluid/PBF/Plan/optimization.md)；流固部分对应根目录 `PBF/`，归档 `demos/PBF_Rigid` 作为算法来源，不将归档的性能混入正式版结果。本次仅整理记录，没有修改或重新测试生产代码。

## 1. 计时口径

- 下文“帧”通常包含 **3 个物理子步，每子步 3 次压力迭代**。纯求解等效 FPS = 1000 / 完整帧毫秒数，不是显示 FPS，也不是物理时间步长的倒数。
- 原版历史：RTX 5070、Warp 1.15.0、frame_dt=1/90。正式流固版本：RTX 5070、Warp 1.18.0、Newton 1.7.0、MuJoCo/MuJoCo Warp 3.15.0、frame_dt=1/150。
- 正式版默认为 195,525 粒子（55×79×45）、r=0.0125 m；“约 50 万”为 494,100 粒子（75×108×61）、r=0.0092 m。均保留原始初始化及地形重叠。
- CUDA-event、同步墙钟、NSYS 时间线分别注明。冻结状态的成对测试与连续演化测试分开；不同批次、不同轨迹或不同规模不拼接成精确累计加速比。多数测试未锁 GPU 时钟。

## 2. 原版 demo 已完成优化

### 第一阶段：减少重复邻域与边界工作

| 已完成手段 | 保留下来的实现与作用 |
|---|---|
| 粒子空间重排 | 位置和预测位置按网格排序，直接使用排序槽位，不恢复原编号 |
| 有效邻域缓存 | 每子步构建一次有效邻居名单，lambda、delta、curl、visvor 复用，避免反复遍历候选并筛选 |
| 缓存布局 | `[邻居槽位, 粒子]`，同槽位的跨线程索引读取连续；当前容量 192 |
| 边界梯度复用 | 每次压力迭代写入 `volume_Grad`，delta 复用同一位置的结果；修正后 SDF 投影仍单独查询 |
| 平滑核与重复代码整理 | 位置参数接口、编译期支持半径、零距离保护；未单独量化性能贡献 |
| 删除重复 grid.build | Epilogue 使用邻域缓存，不再重复建网格；下一子步照常重建 |
| 重置与测试适配 | 工作缓冲、名单计数与边界梯度重置，补充缓冲交换和零梯度等测试 |

205,379 粒子，预热至模拟 20 秒，采集同一时间段 120 帧，NSYS 纯求解 **21.067 → 7.016 ms/帧（下降 66.7%，3.00×）**；CUDA kernels 累计 **19.668 → 6.206 ms/帧**。这是组合改动的收益，没有逐项消融。

该数据仍包含随后删除的重复建网格。删除前估计预算为 0.174 ms/帧，**没有独立整帧 A/B，不再额外扣除或计入实测收益**。

| 核心 kernel | 优化前 → 后，ms/帧 |
|---|---:|
| lambda | 6.960 → 2.136 |
| delta | 7.670 → 1.055 |
| curl | 1.965 → 0.458 |
| visvor | 2.145 → 0.675 |
| 新增 cache_neighbors | 无独立核 → 0.964 |

固定邻居名单不会补入同一子步后续移入支持范围的粒子，这是已接受的算法取舍。旧测量平均约 42.56 个有效邻居、最大 55，只代表该状态，不能据此降低所有场景的容量。公共回调遍历、操作状态结构等尝试已撤回，不列为保留优化。

### 第二阶段：独立体积查询与两层预读

- 将 SDF/VM 查询从 lambda 分离到 `volume_query`，输出 `volume_Rho/volume_Grad`。查询次数不变，目的是减轻流体邻域 kernel 的资源压力。
- lambda、delta、curl、visvor 使用位置提前一位、编号提前两位的预读；保留累加顺序与边界判断。
- A 已包含上一阶段成果；B 仅分离体积查询；C 再加入预读。相同规模从同一 20 秒保存状态恢复，5 批×120 帧，取批次平均耗时的中位数，无 profiler、无渲染。

| 粒子数 | A 原版，ms/帧 | B 分离查询 | C 加预读 | A→C 耗时下降 |
|---|---:|---:|---:|---:|
| 205,379 | 6.522 | 6.015 | 5.524 | 15.3% |
| 405,224 | 11.616 | 10.956 | 10.370 | 10.7% |
| 1,000,000 | 28.102 | 26.132 | 24.229 | 13.8% |

分离查询单步收益约 5.7%～7.8%，随后预读约 5.3%～8.2%，不能直接相加。delta 单核预读收益随规模和批次变化，并非始终为正。历史测试只保证相应单核容差与有限状态；旧阶段多帧轨迹存在差异，不能称为长期逐位一致。

## 3. 正式流固版本：实现基线

根目录 PBF 从原版结构做最小 Newton 适配：保留 kernel/helper、空间排序、邻域缓存和 `Prologue → Solver → Epilogue`，外层持有 Model 与双 State。预测不改输入速度，reorder 直接写输出旧位置，随后原地更新输出位置并重建速度；不恢复编号、不额外完整复制粒子。

新增阶梯场景三个自由刚体（两个盒子、一个球），原地形 boxes 和兔子凸块提供刚体碰撞。采用已验证的压力显式弱耦合：同步边界 → 流体 → 压力反力加入 body_f → MuJoCo → 同步输出边界。压力迭代逐次累计 `F = m·lambda·grad/dt²` 与相对 COM 的力矩；SDF 投影不反馈反力。

GPU MuJoCo Warp、整帧 Graph、重置和交互均已接入。项目自有 kernels 关闭无用 backward 生成；这里没有可比的当前正式版启动加速数字，不量化其收益。Newton 适配本身也不作为性能优化计数。

早期 195,525 粒子完整耦合 Graph 的 NSYS 窗口均值为 **7.588 ms/帧（约 132 等效 FPS）**。同批实际 OpenGL、无 profiler：普通推进 **17.533 ms/帧**，Graph **8.533 ms/帧**，约下降 51.3%。这是独立进程单窗口测量，包含前端成本，不与后面的冻结状态 CUDA-event 数字直接计算累计收益。[早期采集](../outputs/pbf-newton/profiling-20261106/summary.json)

## 4. 动态查询优化：运行时循环与局部粗筛

- 三处刚体循环改为运行时循环，避免每个刚体展开一份大型查询；零动态刚体保留编译期静态快速路径。
- 粒子转到资产局部坐标，先检查统一包围数据，再查询 SDF/VM。包围球和局部盒均实现，代码常量默认选盒，无 CLI 或关闭路径。
- 每资产只计算一次完整网格包围数据，实例共享；压力外扩支持半径，投影外扩粒子半径，另加体素对角线余量。未增加粒子×刚体缓存。
- 保留 delta 两层预读、原反力公式和原子累加；这时反力仍在 delta 内。

195,525 粒子，同一状态与完整 MuJoCo 历史，每组 60 对随机顺序 CUDA-event 采样，计时包含完整耦合 Graph：

| 轨迹检查点 | 原实现 | 仅运行时循环 | 循环＋球 | 循环＋盒 | 盒相对原实现 |
|---|---:|---:|---:|---:|---:|
| 30 帧 | 6.310 ms | 6.039 ms | 5.221 ms | 5.137 ms | 下降 18.6% |
| 180 帧 | 7.482 ms | 7.164 ms | 6.395 ms | 6.289 ms | 下降 15.9% |

球/盒差别较小，后期状态的差别落在波动内，因此按约定选局部盒。连续运行补测：30 帧检查点 **6.858→5.717 ms**，180 帧检查点 **7.550→6.544 ms**。静态与 demo 完整子步对照约 +1.19%，未显著回退。

数值验收含静态 30 子步逐位一致、粗筛临界点/旋转/偏移、共享资产、反力、接触、Graph 奇偶及 10 模拟秒运行。[完整报告](../outputs/pbf-newton/optimization-round1/REPORT.md)

## 5. 压力反力拆分

将 delta 尾部反力原样移到独立 `calc_boundaryForce`，每次迭代变为：

```text
volume_query → calc_lambda → calc_deltaPos → calc_boundaryForce → update_prePos
```

反力仍读取尚未修正的预测位置，仍直接原子累加六个力/力矩分量，零动态刚体不发射此核。没有新增粒子缓冲或规约。delta 寄存器由 **72 降到 42/thread**，独立反力仍为 72；两者均无 local memory。收益主要是让流体邻域计算摆脱反力段的资源负担，不是减少反力数学工作。

494,100 粒子，冻结状态并恢复完整 MuJoCo 历史，30 帧检查点 60 对、180 帧检查点 120 对；CUDA-event 完整耦合帧：

| 检查点 | 融合前 → 拆分后 | 配对耗时下降 | 等效 FPS（按表中耗时） |
|---|---:|---:|---:|
| 30 帧 | 11.167 → 10.456 ms | 6.24%，95% CI 5.01%～8.02% | 89.6 → 95.6 |
| 180 帧 | 12.677 → 11.911 ms | 5.21%，95% CI 3.93%～6.02% | 78.9 → 84.0 |

同批完整流体子步降低约 6.77% / 4.72%，delta＋反力＋投影降低约 17.75% / 12.63%。配对收益是逐对比值中位数，不必等于两组中位数直接相除。连续运行补测分别 **12.326→11.535 ms**、**12.934→12.655 ms**，说明收益也随轨迹改变。

静态 30 子步逐位回归通过，耦合原子加法结果按原容差验收；Graph、重置、外力保留与字段所有权通过。静态相对 demo 子步中位数约 +0.87%，配对区间包含无差异。[正式实现验收](../outputs/pbf-newton/feedback-split/REPORT.md)

## 6. 已测试但未采用的性能方案

| 方案 | 结论 |
|---|---|
| delta 两层预读改一层/其他策略 | 默认耦合场景的实测不足以支持替换；保留两层，不把静态单核改善外推到耦合帧 |
| 反力合入 update_prePos | 与独立核完整帧表现接近，无稳定优势；独立核职责更清楚 |
| warp 内反力规约 | 仍需 leader 原子累加，增加 shuffle；相对直接原子加法没有稳定完整帧收益，部分压力阶段更慢 |
| 调小 block_dim | 未取得足够稳定的整体优势，当前继续使用 256 |

证据：[预读策略](../outputs/pbf-newton/profiling-20261106/delta-strategy-summary.json)、[块大小与拆分实验](../outputs/pbf-newton/optimization-round2/REPORT.md)、[反力位置与规约对照](../outputs/pbf-newton/optimization-round3/REPORT.md)。压力查询有效性复用及更换邻域算法尚未作为生产优化实现。

## 7. CPU 刚体后端与当前表现

初始化代码常量可选 MuJoCo CPU，默认仍 GPU。CPU 路径保留流体子步 Graph，刚体桥接与推进在 Graph 外完成；不下载流体粒子。CPU/GPU 数值、接触、重置、交互和 USD 验收通过。

同一第 180 帧状态、60 对随机采样，设备同步包围的墙钟计时，包含调度、桥接与传输：

| 粒子数 | GPU 整帧 Graph | CPU＋流体 Graph | CPU 普通推进 | CPU Graph 相对 GPU |
|---|---:|---:|---:|---:|
| 195,525 | 5.819 ms | 6.438 ms | 6.953 ms | 配对约慢 10.6% |
| 494,100 | 11.907 ms | 12.967 ms | 13.631 ms | 配对约慢 7.9% |

连续 180 帧平均：默认规模 GPU/CPU **6.243/6.833 ms**，约 50 万 **13.047/13.711 ms**。结论是当前完整 CPU 耦合路径更慢，不等于原生 CPU `mj_step` 本身更慢；桥接、同步和分配没有单独拆分计时。[CPU 后端报告](../outputs/pbf-newton/cpu-backend/REPORT.md)

最近 NSYS（494,100 粒子、预热 180 帧后连续 120 帧、无 OpenGL）为 **12.963 ms/帧，约 77.1 纯求解等效 FPS**。GPU kernel 累计 12.535 ms/帧，主要占比如下：

| kernel | ms/帧 | 占 GPU kernel 累计 |
|---|---:|---:|
| delta | 2.377 | 19.0% |
| cache_neighbors | 2.199 | 17.5% |
| lambda | 2.003 | 16.0% |
| visvor | 1.265 | 10.1% |
| volume_query | 1.151 | 9.2% |
| curl | 0.880 | 7.0% |
| SDF 投影 | 0.738 | 5.9% |
| 独立反力 | 0.549 | 4.4% |

现阶段热点重新集中到流体邻域遍历与属性读取。NSYS 说明时间分布，不能仅凭它判定缓存失效率或寄存器瓶颈。固定名单与两层预读仍是现有优化，不因为成为热点就说明设计错误。[最新采集与分析](../outputs/pbf-newton/review-current/REPORT.md)

## 8. 可以确认的收益与记录边界

- 原版第一阶段：同口径组合优化约 **3.00×**；第二阶段再有 **10.7%～15.3%** 的整帧耗时下降，但不把不同测量阶段拼成新的精确总加速比。
- 正式流固默认规模：运行时循环＋局部盒的可信成对收益约 **16%～19%**；早期 7.588 ms 到当前约 5.8～6.2 ms 可说明整体进展，但跨批次不能作为严格累计收益。
- 约 50 万粒子：反力拆分可信成对收益约 **5%～6%**；缺少该规模最初无粗筛版本的可比基线，因此没有从刚体初次实现到当前的精确累计百分比。
- 最新连续窗口约 77 FPS、冻结状态约 84 FPS 分属不同口径，不矛盾；这些均不是包含显示的实时窗口 FPS。
- 所有收益以保持算法/数值验收为前提。原版历史优化并非全部逐位等价；正式版静态适配及近期优化有独立资源 30 子步逐位回归，耦合结果允许原子累加次序导致的容差内差异。
- 本文保留关键数字，以免依赖被 Git 忽略的本地采集目录。首轮 `boundary-30.json` 的逐样本数据曾被后续冒烟覆盖，现仅保留明确缺失说明；历史汇总、报告和日志仍在，不伪造恢复样本。
